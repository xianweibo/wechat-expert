# 公众号专家 项目规则

> 写给所有 AI 助手。涉及本项目时必须遵守。

---

## 1. B 站 API 访问 — 必须走阿里云网络

### 背景

**沙箱和 NAS 已被 B 站风控永久拉黑**（返回 -412 banned / -352 风控校验失败 / -799 频率限制）。

只有**阿里云容器（8.134.248.11）**的 IP 仍在 B 站白名单内。所有 B 站 API 调用必须从阿里云发出去。

### 规则

| 环境 | 是否可直连 B 站 API | 处理方式 |
|---|---|---|
| 沙箱（Windows + curl） | ❌ 已封 | **禁止**直连，必须经阿里云中转 |
| NAS（Docker 192.168.9.3） | ❌ 已封 | gzh-worker 已停摆，代码需迁移到阿里云 |
| 阿里云容器（8.134.248.11） | ⚠️ search/dynamic 已 -352 captcha（2026-06-15 发生） | **仅** `x/web-interface/view` 仍可用；search 路线彻底死 |

### 实施方式

- 沙箱代码要查 B 站数据时，**必须**调用 `http://8.134.248.11:39800/api/admin/bilibili-*` 这类端点
- 阿里云 app `gzh-expert-app` 是 B 站请求的代理出口
- 任何添加的 B 站调用端点都要部署在阿里云 app 里，不要再部署到 NAS 的 gzh-worker

### ⚠️ 阿里云 IP 也被风控后的应对（2026-06-15 更新）

- **阿里云 search/dynamic API 已被永久风控**（不再只是临时 -799）
- **唯一可用**：`x/web-interface/view?bvid=...`（必须已知 BVID）
- **意味着**：自动扫"今天 12:00 充电视频"这条路断了——必须用户手动提供 BVID
- **流程改为**：
  1. 用户从 B 站 APP 复制"充电视频"页面的 BVID 发给 AI
  2. AI 用 view API 拿 title/desc/pubdate
  3. MiniMax 出 cover + 出 LLM 总结 → 走 mp_proxy 建草稿

### 风控注意事项（阿里云也要小心）

- 单次任务内**对同一 B 站 API 的调用间隔 ≥ 2 秒**（详见 `gzh-worker/src/bilibili.ts` 的 `withRetry` 实现）
- B 站动态 API (`x/polymer/web-dynamic/v1/feed/space`) 失败就**不要**马上重试，切到常规 `x/space/wbi/arc/search` 备份路径
- 任何"刷所有视频列表"的请求都会触发风控，**优先用动态 API 只取最近 N 条**（N ≤ 30）
- SESSDATA cookie 90 天过期，**过期前 1 周**主动更新；`bili_jct` 跟着换

### 检测命令

如果收到下列 B 站响应，**立即停止**所有 B 站相关操作并告警：

```json
{"code": -412, "message": "request was banned"}
{"code": -352, "message": "风控校验失败"}
{"code": -799, "message": "请求过于频繁，请稍后再试"}
```

## 2. 沙箱环境其它约束

- 中文 PowerShell 路径会 mojibake，**写脚本用 `Get-Location` / `Join-Path` 而不是写死中文路径**
- 中文 JSON 内容走 mp_proxy 时如果解析失败，**改用纯文本（去掉 HTML 标签）**
- 沙箱无 `nc`，SSH 代理（127.0.0.1:18080）走 HTTP only，**HTTPS 要绕开 B 站**
- MiniMax image-01-live 走 `response_format=url` 拿 OSS 链接，**最稳**（沙箱 TLS 收不了大多数图床）

## 4. 草稿内容约定（2026-06-15 跟用户敲定）

> 用户原话：约定以后视频来源不用粘贴，然后视频的简介里面的 fyi 可以粘贴放到最底。
> 补充（2026-06-15）：模型换成 minimax-M3，**免责声明里不要写"由 AI 生成"**。

### 草稿结构（按从上到下）

0. **作者**：`author` 字段固定填 `小喇叭大只讲`（2026-06-15 跟用户敲定）
1. **封面图**：anime 风格，主题相关，16:9，由 `image-01-live` 生成
2. **顶部声明块**（紧跟封面之下、LLM 总结之上）：
   - 4 行声明文字（用 `<br/>` 换行）
   - **3 行空行**（`<p></p><p></p><p></p>`）
   - `---` 分隔符（用 `<p>---</p>`，显式文本不用 `<hr/>`）
   - **1 行空行**（`<p></p>`）
   ```
   <p>内容不作为投资建议，注意风险。<br/>
   都是历史数据，仅作为学习。<br/>
   独立学者：<br/>
   没想到啊，我才没休息几天又可以玩了。</p>
   <p></p>
   <p></p>
   <p></p>
   <p>---</p>
   <p></p>
   ```
3. **正文 LLM 总结**：由 **minimax-M3**（即当前 AI 助手）直接生成，1000-1500 字，5-8 个要点
   - 每点 100-200 字论述
   - 通俗语言，不复述原话，不预测涨跌
   - 末尾加"总结"段落
   - **不需要** 再调 MiniMax LLM API
4. **FYI 列表**
   - 视频简介里提到的所有参考链接逐条粘贴
   - 格式：`<标题> — <URL>`，纯文本超链接
5. **底部声明块**（FYI 之后）：
   - **1 行空行**（`<p></p>`）
   - `---` 分隔符（`<p>---</p>`）
   - **1 行空行**（`<p></p>`）
   - `Make you greate again！`（`<p>Make you greate again！</p>`）
   - **1 行空行**（`<p></p>`）
   - 声明文字（用 `<br/>` 换行）
   ```
   <p></p>
   <p>---</p>
   <p></p>
   <p>Make you greate again！</p>
   <p></p>
   <p>=======</p>
   <p>=</p>
   <p>以下不是建议<br/>
   只是根据历史数据,量化模式回测<br/>
   都是历史数据和我本人的记录，不作为建议荐股！！！<br/>
   每天都更新，仅供学习</p>
   <p>=</p>
   <p>=======</p>
   <p>PS：<br/>
   最后的最后<br/>
   不指导、不建议、不入群，都是前一天历史数据分析，根据量化模型回测出来，不构成投资建议。<br/>
   股市有风险，投资需谨慎<br/>
   股票池：<br/>
   以下的都是公司企业，不是股票推荐</p>
   ```

### 显式 **不要** 粘贴

- ❌ BVID
- ❌ UP 主名
- ❌ 发布日期
- ❌ "📺 来源：..." 块
- ❌ 视频时长
- ❌ "参考链接" 标题（用 "FYI" 替代）
- ❌ "由 AI 生成" / "由 minimax-M3 生成" 等模型/出处声明

```
你是一个财经学习内容整理助手。请根据以下视频字幕和简介，生成一段精华总结。

视频标题：{title}
视频简介：
{desc}
字幕内容：
{subtitle_text | '（无字幕）'}

要求：
- 提取核心要点，分5-8个要点详细展开
- 用通俗易懂的语言
- 不复述原话，用自己语言重构
- 保持中立，不预测涨跌
- 篇幅控制在1000字左右，内容要充实有深度
- 每个要点要有充分的论述和分析，不要只是简单罗列
```
